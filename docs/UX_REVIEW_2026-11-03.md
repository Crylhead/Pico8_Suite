## 1. Pixel Studio preview: deterministic reproduction

Source: [`js/studio.js` preview renderer](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/studio.js#L527-L544), [click handler](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/studio.js#L3038-L3047), [markup](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/index.html#L924-L930) and [CSS container](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/css/suite.css#L495-L505).

The handler is live, persists the choice and schedules a redraw. The `drawPreview` formula is equivalent to:

```js
const limit = 176;
const auto = Math.max(1, Math.floor(limit / Math.max(docWidth, docHeight)));
const requested = selectedScale || auto;
const forcedFit = Math.min(1, limit / (docWidth * requested), limit / (docHeight * requested));
const renderedWidth = Math.round(docWidth * requested * forcedFit);
const renderedHeight = Math.round(docHeight * requested * forcedFit);
```

| Document dimensions | Auto result | 1× result | 2× result |
| --- | --- | --- | --- |
| 32×32 | 160×160 | 32×32 | 64×64 |
| 64×64 | 128×128 | 64×64 | 128×128 |
| 128×128 (default) | 128×128 | 128×128 | 176×176 |
| 128×256 | 88×176 | 88×176 | 88×176 |
| 256×256 | 176×176 | 176×176 | 176×176 |
| 1024×512 | 176×88 | 176×88 | 176×88 |

The exact **no-op** is present for common documents larger than the 176 px preview box; for smaller documents, Auto may scale, but not necessarily fit the available area. `imageSmoothingEnabled = forcedFit < 1` can also blur enlargement (e.g. a 128×128 image displayed 176×176 when 2× selected). A responsive side-panel splitter does not affect this hard-coded cap.

**Recommended behavior:** rename to **Fit** and implement actual container-fit; 1× and 2× must retain their literal zoom factors, with explicit scroll/pan instead of silent fallback. Keep pixel-art scaling crisp; allow zoom indicator and consistent keyboard/ARIA state. Include representative dimension-specific regression cases and real browser verification.

Today there are exactly **three built-in tour definitions**: `suite`, `studio`, `terrain`. An orientation tour should **point to major regions** and explain purpose and handoff, not enumerate every checkbox or repeat the entire manual. The tours are already optional and replayable; preserve that. New tours should be maintainable with stable targets and central help IDs.

The existing [`tests/docs-integrity.js`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/tests/docs-integrity.js) enforces one help entry per workspace and validates **present** tours, but does not fail when an entire workspace or Extra Tools subtool has no tour. #103 and #109 address content and prevention respectively.

## 3. Interaction and consistency follow-ups

- **Tooltips:** [`.ux-tip { pointer-events: none }`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/css/suite.css#L1095-L1099) prevents hovering the tooltip itself; [tooltip leave handler](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/ux-tooltips.js#L116-L135) hides it. This conflicts with [WCAG 2.2 hover/focus guidance](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html), while its Escape and focus logic are positive features to preserve. See #104.
- **Help detail Off:** Settings promises optional tooltips will be suppressed. [`claimTitles`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/ux-tooltips.js#L145-L165) only manages elements with `data-help-id`; unrelated native explanatory `title` attributes remain. Do not remove native titles blindly if they provide an accessible name. See #107.
- **F1 routing:** [`showHelp`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/app.js#L1569-L1578) reads only workspace/explicit topic, not the focused help control or Extra Tools subtab. The help catalog has one generic Extras entry, so Terrain/Wave/LUT/Line need better context-sensitive routing. See #106.
- **Help sparsity:** the static UI has five `data-help-id` markers while the central catalog has many more action/control entries; primary areas such as Preview scaling have no contextual explanation. Add meaningful control coverage rather than blanket annotation of every button. See #110.
- **Tour discovery:** [`showTours`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/tours.js#L120-L151) provides a flat global list; once complete, add context-specific Tour this Tool and grouped discovery. See #108.
- **Tour progress:** [`tours.js`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/tours.js#L88-L108) prints a raw index from the step plan. Conditional skipped steps can make numbers jump. Clarify progress when enhancing the two existing tours (#105).
- **About:** [`showAbout`](https://github.com/Crylhead/Pico8_Suite/blob/37268fc6c28f04f850753531dbf8ac9fc636cf7d/js/app.js#L1876-L1910) has a static old graphics-oriented feature list, not reflecting the full modern IDE-like suite. See #111.

1. **Immediate independent fixes:** #102 Preview scale and #104 tooltip hover accessibility. Distinct CSS/JS areas but coordinate `css/suite.css` edits. Both are testable on a minimal UI fixture.
2. **Core user onboarding:** #103 all missing tool tours (one or several non-overlapping data/content PRs), then #109 tour coverage integrity (merge test only when metadata is complete).

4. **Polish:** #105 improve Pixel Studio/Terrain tours after #102; #108 tool-local tour selection after #103; #111 About dialog refresh independently.

Each PR must satisfy its own acceptance criteria, preserve advanced workflows and follow `AGENTS.md` proportional testing. Suggested browser checks: 32/64/128/256/1024 px image previews; all tours from each workspace, including dynamic Extras tabs; F1 with focused controls and tab variants; tooltip mouse-to-card movement, Escape, Help Off, zoom and narrow viewport; About dialog and optional Help from keyboard. Do not imply that synthetic tests substitute for true browser behavior.
